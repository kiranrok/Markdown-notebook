## Read this first (simple words)

If this is your first time seeing the notebook, ignore the long architecture section until this makes sense.

### What is an “agent” here?

An **agent** is a chatbot that can **use tools**. A tool is a function it can call, like “search the web” or “run SQL.” The model decides *when* to call a tool. Then it reads the result and answers.

This notebook has **four** agents, not one.

### Everyday picture

Imagine you are planning a wedding and you hire a **wedding planner**.

The planner does not book flights, scout venues, and pick songs themselves. They write down your details, then call three people:

| Person | Job | In the code |
| --- | --- | --- |
| Wedding planner | Listens to you, writes notes, asks the three specialists, gives you one plan | **Coordinator** |
| Travel agent | Finds flights | **travel_agent** |
| Venue scout | Finds a hall | **venue_agent** |
| DJ | Picks songs | **playlist_agent** |

You only talk to the planner. The three specialists never talk to you, and they never talk to each other.

### What you type

> I'm from London and I'd like a wedding in Paris for 100 guests, jazz-genre

Four facts are hiding in that sentence:

1. You start in **London**
2. The wedding is in **Paris**
3. You have **100 guests**
4. You want **jazz** music

The planner’s first job is to **write those four facts down**. In the code that notebook is called **state** (a small shared notepad).

### Why a notepad? (state)

If the travel person asks “where from / where to?”, they should not re-read your original paragraph. They should look at the notepad:

- origin = London  
- destination = Paris  
- guest_count = 100  
- genre = jazz  

The tool that writes the notepad is **`update_state`**.  
**This must happen first.** If the planner asks for flights *before* writing the notepad, the travel person has nothing to read.

### Then the three jobs

After the notepad is filled:

1. **Flights** — look up real flight-style results using Kiwi (an outside flight service). The code talks to it through **MCP** (think: a standard plug so the agent can use someone else’s tools).
2. **Venues** — search the web (Tavily) for halls in Paris that can fit 100 people. The code **limits how many searches** so it does not search forever.
3. **Playlist** — look in a sample **music database** (Chinook, like a practice Excel of songs) and pick jazz tracks, then add up time and price.

Each specialist only has **their** tools. The DJ cannot search flights. The travel agent cannot query the song database.

### Then one answer

Each specialist sends a short report back to the planner. The planner writes **one** wedding plan for you (flights + venue + songs together).

That last printed message in the notebook is the thing you show the class.

### Tiny dictionary (words you will see in the notebook)

| Fancy word | Simple meaning |
| --- | --- |
| **Tool** | A function the agent is allowed to call |
| **State** | The shared notepad (London, Paris, 100, jazz) |
| **Coordinator** | The wedding planner agent |
| **Specialist / sub-agent** | Travel, venue, or playlist agent |
| **MCP** | A way to plug in tools from another server (here: Kiwi flights) |
| **Interceptor / retry** | If the flight website fails, try again; if it still fails, tell the agent in words instead of crashing |
| **Tavily** | A web-search API used to find venues |
| **Chinook / SQLite** | A small local music database the playlist agent queries with SQL |
| **`create_agent`** | LangChain helper that builds “model + tools + prompt” |
| **`runtime.state`** | “Read the notepad” from inside a tool |
| **`Command(update=...)`** | “Write these fields onto the notepad” |
| **LangSmith / tag WP** | Optional website that shows the step-by-step trace of the run |
| **`recursion_limit=40`** | Allow many back-and-forth steps (planner + nested specialists) |

### Simple architecture (the only diagram you need at first)

```
YOU:  "London, Paris, 100 guests, jazz"
              │
              ▼
     WEDDING PLANNER  (coordinator)
              │
              │  1. Write notepad: London / Paris / 100 / jazz
              │
              ├──► Travel person  ──► flight website (Kiwi)
              ├──► Venue person   ──► Google-like search (Tavily)
              └──► DJ             ──► music database (Chinook)
              │
              ▼
     ONE wedding plan back to you
```

### What happens if something breaks? (simple)

- Flight website is down → the code **retries**, then tells the travel agent “it failed” in text, so the agent can try again instead of the whole notebook exploding.
- Venue search goes on too long → after a max number of searches, the tool says **stop and summarize**.
- Bad SQL for songs → the database returns an **error message**, and the DJ agent rewrites the query.

## 3. Architecture (use this on the board / in slides)

This is a **supervisor (coordinator) + specialists** pattern. The coordinator owns **shared state**. Specialists are **nested agents**, each with its own tools and prompt. They never share a chat history with each other.

### 3.1 System context (what talks to what)

```
                         ┌─────────────────┐
                         │  Human / class  │
                         └────────┬────────┘
                                  │ one sentence
                                  ▼
                    ┌─────────────────────────────┐
                    │  Coordinator graph          │
                    │  create_agent(...)          │
                    │  state_schema=WeddingState  │
                    └──────────────┬──────────────┘
           ┌───────────────────────┼───────────────────────┐
           ▼                       ▼                       ▼
    Travel subgraph         Venue subgraph          Playlist subgraph
    (own messages)          (own messages)          (own messages)
           │                       │                       │
           ▼                       ▼                       ▼
    Kiwi MCP HTTP            Tavily API              Chinook SQLite
    mcp.kiwi.com             web_search              resources/Chinook.db
    + Retry interceptor      + search cap
```

**External systems**

| System | Protocol | Used by | Role |
| --- | --- | --- | --- |
| OpenAI (`gpt-5-nano`) | API | All four agents | Reasoning + tool choice |
| Kiwi MCP | streamable HTTP | Travel only | Flight search tools (discovered at runtime via `get_tools()`) |
| Tavily | HTTP | Venue only | Web search for venues |
| Chinook | local SQLite | Playlist only | Tracks, genres, duration, price |
| LangSmith (optional) | traces, tag `WP` | Observability | Debug nested runs |

### 3.2 Component architecture (code objects)

```

                                      ▲
                                      │ Command(update=...) from update_state
                                      │ runtime.state read by specialist tools
┌──────────────────────────────────────────────────────────────────────────┐
│ Coordinator                                                              │
│   model: gpt-5-nano                                                      │
│   tools:  update_state | search_flights | search_venues | suggest_playlist│
│   prompt: extract → update state alone → delegate → assemble             │
└──────────────────────────────────────────────────────────────────────────┘
        │ search_flights          │ search_venues         │ suggest_playlist
        │ origin, destination     │ destination,          │ genre
        │                         │ guest_count           │
        ▼                         ▼                       ▼
┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
│ travel_agent     │    │ venue_agent      │    │ playlist_agent   │
│ tools = MCP list │    │ tools=[web_search]│   │ tools=[query_    │
│                  │    │                  │    │   playlist_db]   │
└────────┬─────────┘    └────────┬─────────┘    └────────┬─────────┘
         ▼                       ▼                       ▼
┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
│ MultiServerMCP   │    │ TavilyClient     │    │ SQLDatabase      │
```

**Isolation rule:** travel cannot call Tavily or SQL; venue cannot call Kiwi; playlist cannot search the web. The coordinator is the only component that sees all three answers.

Specialist calls may be **sequential or parallel** depending on what the coordinator model emits in a given run. The **must-not-change** order is: **`update_state` completes before any specialist tool**.

### 3.4 State and data flow

`WeddingState` is the **contract** between coordinator and specialists.

| Field | Example | Written by | Read by |
| --- | --- | --- | --- |
| `messages` | full coordinator thread | LangGraph / tools | coordinator |
| `origin` | `"London"` | `update_state` | `search_flights` |
| `destination` | `"Paris"` | `update_state` | `search_flights`, `search_venues` |
| `guest_count` | `"100"` | `update_state` | `search_venues` |
| `genre` | `"jazz"` | `update_state` | `suggest_playlist` |

How a specialist is invoked (pattern):

```
runtime.state["destination"]  +  runtime.state["guest_count"]
        │
        ▼
HumanMessage("Find wedding venues in Paris for 100 guests")
        │
        ▼
venue_agent.invoke({ "messages": [that message] })
        │
        ▼
return response["messages"][-1].content   →   ToolMessage on coordinator thread
```

The specialist graph has **its own** `messages`. Only the **final string** is copied back. That is why specialists are told not to ask follow-up questions: they have no channel back to the human except through the coordinator.

`update_state` does not return a normal string as the graph update. It returns:

```
Command(update={
  origin, destination, guest_count, genre,
  messages: [ToolMessage("Successfully updated state", tool_call_id=...)]
})
```

LangGraph merges the four fields into `WeddingState` and appends the tool result so the coordinator can continue.

### 3.5 Nested graphs and step budget

```
coordinator.ainvoke(..., config={ tags: ["WP"], recursion_limit: 40 })
        │
        │  each create_agent is a LangGraph
        │
        ├── travel_agent.ainvoke   ← can loop: MCP tool → observe → MCP again
        ├── venue_agent.invoke     ← can loop: web_search 1..12 then stop
        └── playlist_agent.invoke  ← can loop: SQL error → rewrite query
```

`recursion_limit=40` is on the **outer** graph. Nested agents add their own steps. Without a higher limit, the run dies mid-delegation.

### 3.6 Error-handling architecture (why the lab was updated)

```
MCP call
  │
  ├─ success ──────────────────────────► tool content
  ├─ McpError code in {-32603} ───────► retry (backoff 1s, 2s, 4s)
  ├─ other McpError ──────────────────► text result, isError=False
  └─ network / other Exception ───────► retry, then text, isError=False

web_search
  ├─ search_number > max ─────────────► "Search limit reached..."
  └─ Tavily exception ────────────────► {"error": "..."}

query_playlist_db
  └─ SQL exception ───────────────────► "Error querying database: ..."
```

Design rule for the demo: **prefer returning an error the model can read over raising**, so the agent can change arguments and continue.

## 4. Walkthrough of the code (what to say as you scroll)

### Cell 0 — env

`load_dotenv()` loads API keys (OpenAI, Tavily, LangSmith if used). Confirm `.env` is present before class.

### Kiwi MCP + `RetryMCPInterceptor`

- `MultiServerMCPClient` talks to `https://mcp.kiwi.com` over **streamable HTTP**.
- Real MCP/network calls fail. The interceptor:
  - retries code **`-32603`** (and generic exceptions) with backoff `2 ** attempt`;
  - for non-retryable MCP errors (e.g. `-32602`), returns immediately;
  - after retries, returns a **text** `CallToolResult` with **`isError=False`**.

**Talking point:** `isError=False` keeps the failure in the **message list as content**, so the travel agent can retry instead of the graph dying.

### `web_search` (Tavily)

Venue agent must pass `search_number` and `max_search_number`. If `search_number > max_search_number`, the tool **refuses** another search and tells the model to summarize.

ASCII-only queries: Tavily can choke on accents (`capacité` → `capacite`).

### `query_playlist_db`

Chinook DB at `sqlite:///resources/Chinook.db`. SQL errors come back as **strings** so the playlist agent can rewrite the query (prompt says: discover schema first, never return empty-handed).

### `WeddingState`

Extends `AgentState` with four strings. Specialists do not parse the original user message; they read these via **`ToolRuntime` / `runtime.state`**.

### Three specialists (`create_agent`)

| Agent | Tools | Prompt constraint |
| --- | --- | --- |
| Travel | MCP tools from Kiwi | No follow-up questions; one-way, cheapest economy, shortest, “best wedding season”; retry if MCP is junk |
| Venue | `web_search` | No follow-ups; price, capacity, reviews; ~12 searches then stop |
| Playlist | `query_playlist_db` | Schema first; total duration + cost; keep querying until you have songs |

Model in the notebook: **`gpt-5-nano`**.

### Coordinator tools

- `search_flights` / `search_venues` / `suggest_playlist`: pull fields from `runtime.state`, build a **HumanMessage**, `ainvoke`/`invoke` the sub-agent, return **last message content**.
- `update_state`: returns `Command(update={...})` **plus** a `ToolMessage` so the graph records a successful tool result and the new state.

## 8. Questions you should be ready for

**Why not one agent with all tools?**  
Separation of prompts and tool sets. Travel must not web-search venues; playlist must not call Kiwi. State is the **contract** between coordinator and specialists.

**Why `update_state` alone?**  
If it is batched with `search_flights` in the same step, specialists may run **before** state is written and read empty/missing fields.

**Why `Command` instead of returning a string?**  
`Command(update=...)` is how LangGraph merges custom state **and** appends the `ToolMessage` in one tool result.

**Why `ainvoke` on flights but `invoke` on venues/playlist?**  
Flights go through async MCP. Venues/playlist are sync HTTP/SQLite. Mixed is fine; coordinator `ainvoke` still works.

**Why `recursion_limit=40`?**  
Each specialist can loop (search, SQL retries). Default graph step limits are too low for nested agents.

**Is Chinook a real wedding catalog?**  
No. It is the sample music DB (tracks, genres, prices) so SQL-as-tool is demoable without a custom dataset.
